# Fast Inference from Transformers via Speculative Decoding (Leviathan, Kalman & Matias, 2023)

**Source:** https://arxiv.org/abs/2211.17192  **License:** Creative Commons Attribution 4.0 (CC BY-4.0), per the arXiv license badge on the abstract page

## What it does

This paper speeds up how a big language model produces text, without changing a single word of what it outputs. The trick is to let a small, cheap model race ahead and guess several tokens at once, then have the big model check that whole guess in one pass instead of grinding through the words one at a time. Most of the guessed tokens turn out to be right, so the big model effectively "catches up" for free on the ones it agrees with, and only pays full price on the rare disagreement. The paper proves mathematically that this shortcut produces exactly the same probability distribution over outputs as running the big model alone — it is a speed trick, not an approximation. On their tested models the method delivered 2-3x real wall-clock speedups with no retraining and no change to model architecture. It was accepted as an oral presentation at ICML 2023.

## Method

Every decoding step normally costs one full forward pass of the big "target" model per token, and that pass is dominated by memory bandwidth, not arithmetic — the model spends most of its time loading weights, not computing with them. Speculative decoding exploits this by having a much smaller, cheaper "draft" model autoregressively propose gamma tokens in a row (gamma is a tunable lookahead depth, e.g. 3-7). Then the target model runs a single forward pass over the whole proposed sequence at once — something GPUs/TPUs can do almost as cheaply as a single-token pass, since it's now compute-bound rather than memory-bound for that batch.

The clever part is how tokens get accepted or rejected. For each drafted token, the algorithm compares the draft model's probability q(x) to the target model's probability p(x) for that same token. If q(x) is less than or equal to p(x), the token is kept outright. If the draft model was overconfident (q(x) greater than p(x)), the token is only kept with probability p(x)/q(x), and if rejected, a fresh token is sampled instead from a corrected residual distribution (roughly, "what's left over" after subtracting the draft's mass from the target's). This "speculative sampling" step is what makes the guarantee airtight: it can be proven that the tokens coming out of this accept/reject dance are distributed identically to what the target model alone would have sampled. As soon as one token is rejected, everything after it in that batch is discarded and the target model's own correction is used instead — so a run of gamma guesses yields anywhere from 1 to gamma+1 tokens per big-model pass.

The paper derives a closed-form expected speedup: (1 − alpha^(gamma+1)) / ((1 − alpha)(gamma·c + 1)), where alpha is the average per-token acceptance rate and c is the cost ratio of one draft-model step to one target-model step. This makes explicit that the whole scheme is a bet: you win by how often the cheap model agrees with the expensive one (alpha), discounted by how much the cheap model costs to run (c) and how far you dare to look ahead (gamma).

## Key findings

- Target T5-XXL (11B) paired with draft T5-small (77M): acceptance rate alpha 0.62-0.75
- Target T5-XXL paired with draft T5-base (250M): alpha 0.68-0.80 (better agreement, but a pricier draft)
- LaMDA 137B target with an 8B LaMDA draft: alpha 0.74-0.75
- A crude bigram model used as draft only reached alpha 0.19-0.23 — a weak draft barely helps
- Wall-clock speedup on WMT English-German translation with T5-XXL: 3.4x with argmax (greedy) decoding, 2.6x with standard temperature sampling
- Wall-clock speedup on CNN/DailyMail summarization with T5-XXL: 3.1x argmax, 2.3x standard sampling
- Total arithmetic operations increase 1.11x-1.96x depending on alpha/gamma choice — more raw compute is spent, but wall-clock time drops because the bottleneck (memory-bound sequential passes) is what's being amortized
- Output distribution is provably identical to standard sampling from the target model — no quality tradeoff, confirmed both in theory and empirically
- Also tested on unconditional language generation (lm1b) and LaMDA-based dialog, with similar directional gains

## What Tilde should take from it

Tilde already runs a bundled ~2B-class base model on-device for autocomplete, and separately has an on-device n-gram next-word model sitting unpromoted, waiting for a serving role. Speculative decoding is almost exactly the shape of problem that n-gram model was built for: instead of only using it as a fallback signal or for standalone predictions, it could serve as the "draft" model that proposes the next word (or few words), which the 2B model then verifies in a single forward pass. Because Tilde's suggestion is often already just one or a few tokens for autocomplete (not long free-running generation), the acceptance-rate dynamics here matter directly — the paper shows that even a weak-but-cheap draft (their bigram baseline) still gives non-zero lift, and a stronger local model (like Tilde's trained n-gram) should land closer to the 0.6-0.8 acceptance rates seen with T5-small/T5-base drafts, especially on personal, low-entropy text where the user's own phrasing is predictable.

The bigger point for Tilde's north-star metric (keystrokes saved, with latency as a hard constraint under "must help more than interrupt") is that this technique targets exactly the failure mode Tilde cares about: end-to-end latency of the local model, which the docs already flag as a friction source (the ~450ms first-token budget, phase instrumentation work). Speculative decoding is a way to cut wall-clock latency 2-3x with zero quality loss and zero retraining — it doesn't require a new eval, doesn't touch EM@1 or keystrokes-saved as a metric, and is purely a serving-layer win. Given Tilde already has a small local model as the workhorse, the realistic win is smaller than the paper's target/draft size gap (base model isn't 11B, so c — the cost ratio — is less favorable), but even the paper's guidance to tune gamma against measured alpha and c is directly actionable: instrument acceptance rate between the n-gram and base model, then pick a lookahead depth that pays off on-device rather than guessing.

## Limits and caveats

The paper's target models (T5-XXL 11B, LaMDA 137B) are far larger than Tilde's bundled ~2B model, and the speedup math is most favorable exactly when the target model is huge and memory-bound and the draft model is comparatively tiny (c small). With a 2B target, the target model's own forward pass is cheaper to begin with, so the batched-verification trick has less memory-bandwidth slack to exploit — the achievable speedup on Tilde's model size is very unlikely to hit the 2-3x seen in the paper and needs to be measured, not assumed. The experiments are on server-class TPU/GPU hardware doing batch decoding for translation and summarization, not the single-user, single-sequence, on-device Apple Silicon setting Tilde runs in, where kernel launch overhead, thermal/power constraints, and Metal/CoreML batching behavior differ substantially from the paper's infrastructure. The guarantee of "identical output distribution" assumes exact-precision matching between how logits are computed for the draft and target proposals; quantized or CoreML-converted models can introduce small numerical divergences that this scheme is not designed to tolerate perfectly. Finally, the technique speeds up generation of a given output — it does nothing to change what gets generated, so it cannot substitute for or inform Tilde's personalization or eval work; it's purely a latency lever to pull once acceptance-rate and cost-ratio numbers are actually measured on-device.
