# Docs Folder Guide

Keep docs short and decision-oriented.

- Product docs belong in `product/`.
- Research notes belong in `research/`.
- Keep one current source of truth for architecture, development, privacy,
  compatibility, and release process.
- Do not add dated scorecards, run logs, or comparison stacks unless an
  executable proof gate consumes them.
- Do not let docs imply users must manage external model services.
